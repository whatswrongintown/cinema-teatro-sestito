# Prioritized implementation guide

Updated on 2026-11-23 from the current project status. This guide contains steps
for open, deferred and planned work; completed outcomes remain in the status
record. Recommendations here do not implement or resolve an item.

## How to use this guide

- **P1 - High:** remove accessibility barriers, misleading navigation or
  misleading interpretation; maintain existing form operations.
- **P2 - Normal:** correct configuration, metadata and editorial issues, or
  deliver planned work after its prerequisites are satisfied.
- **P3 - Later:** optional polish and features with unresolved scope.
- For every completed change, update its ID in [project status](../project-status.md)
  with evidence and date.
- Do not hand-edit `public\`, `resources\` or generated programming tables.
  Netlify runs Hugo, not R.
- Preserve historical URLs, the Progetto-only main menu, approved privacy
  decisions and the no-chart-recalculation decision unless separately agreed.

## H01-H07: Migration to Hugo only

Decided by the owner on 2026-11-23. Goal: the site is generated by Hugo alone,
so that it can evolve without a local R build step. R and RStudio remain for
exploratory analysis of the datasets only, never as part of the site build.

General rules for every step:

- One step per change. Before replacing a generator, record the current output
  (pages, URLs, tables, front matter) and compare it with the Hugo output.
  Identical URLs and equivalent content are required; aliases for any change.
- Keep the CSVs in `static/data/` as the single source of truth. They are final
  (2026-11-23), so a step may also simply keep the committed generated pages
  and remove the R generator, if Hugo templates bring no real benefit.
- Remove an R script, its test and its documentation only after its Hugo
  replacement is built, compared and published.
- Hugo 0.136.5 stays pinned unless an upgrade is separately agreed. Note that
  `excludeFiles` (mounts) and `languageCode` change in later versions.

Recommended order:

1. **H01 - Hugo as the local tool (DONE 2026-11-23).** Use `hugo server` / `hugo` instead of
   `blogdown::serve_site()` / `build_site()`. Update README, docs and the RStudio
   project (`BuildType: Website`). `.Rprofile` and `index.Rmd` can go once no
   blogdown workflow remains (after H02).
2. **H02 - Rmd articles to Markdown (DONE 2026-11-23).** Convert the 2023 and 2025 article
   `index.Rmd` files: keep the existing committed `index.md`, save the charts as
   files in the page bundle, remove the `.Rmd` sources and, if unused, the
   `layouts/shortcodes/blogdown/` shortcode and the Rmd mount exclusions in
   `config.yaml`.
3. **H03 - Historical programming in Hugo (DONE 2026-11-23).** The
   `programmazione-tabelle` and `grafico` shortcodes render tables and SVG
   charts from the CSVs; see the
   [guide](../guides/historical-programming.md).
4. **H04 - Poster collection in Hugo (DONE 2026-11-23, see project status).** Generate film and browse pages in Hugo
   from `data/posters/films.json` or the CSVs. The web images in
   `static/images/manifesti/` are final: reuse them unchanged; no image
   derivative step is needed.
5. **H05 - Dashboard in Hugo (built 2026-11-23; retire Shiny after publication).** Replace the Shiny app and its iframe with a
   Hugo page (data from the CSVs, client-side filters). Keep Shiny live until the
   replacement is published, then retire the shinyapps.io deployment.
6. **H06 - Source PDF conversion (DONE 2026-11-23: retired, no tool kept).** Replace `R/fonti_pdf_to_images.R` with a
   documented non-R local tool (for example ImageMagick/pdftoppm), or keep it as
   a rare manual utility if the owner prefers.
7. **H07 - Clean-up.** Remove replaced R scripts, tests and guides; move any
   analysis code to a non-build folder (for example `analysis/`) excluded from
   Hugo; update CLAUDE.md, README and project status.

## F03: Film search

**Priority:** P3. **Depends on:** agreed result granularity and search scope.

1. Agree whether each result is a film, screening or poster, the searchable
   fields, partial matches, accents and case. Release year and screening year
   remain distinct.
2. Build the index with Hugo (JSON output from the CSVs), not R, in line with
   the migration. Exclude private form submissions.
3. Create an accessible Italian search page with loading, empty-query,
   no-results and failure states; keep browse pages as the no-JavaScript
   alternative.
4. Test accents/case, partial titles, ambiguous titles, repeated screenings,
   missing metadata and keyboard use; add the page to `content/sitemap.md`.
